# houji 的 Block Ack 与 A-MPDU 路线

2026-11-10 源码审计。比对 Owly `6f2e8ea99aed0687558d78a1dd49154ab3a5fa76`、Wonder/WLAN 覆盖层 `5a8fc70d06dcf2c99feb956fc74d8cbafbf8a7ce`，以及 `build-host:/work/houji-build/src/wideband/wlan` 的实际宽带候选树。后者的 Qualcomm 基础提交是 `a4da9e3b43864da13bc978b8cb6385ba5332a4af`，并叠加 [重建和实验补丁](06-driver-build.md)。远端 `dp_rx_tid.c`、`lim_process_action_frame.c` 的 SHA-256 均与该提交公开原文件一致。本轮未切换设备、发送 BA 管理帧或改动固件。

**目前确认的是软件 A-MSDU，PASSTHRU 固件 TX 合包配置上限为 1。** 软件 A-MSDU 把多个 MSDU 放进一个 MPDU。A-MPDU 让同一接收端和 TID 的多个独立 MPDU 共用一次发送，每个 MPDU 保留自己的序号，接收端的 Block Ack 以序号窗口和位图报告接收状态。现有 6.470 MB/s 是小米→Mac 的软件合包结果。此前 2.575 MB/s 的 Mac→小米重复平均给了优先研究 **小米作为 BA 接收端** 的理由，收益仍待实测。 [实测数据](14-owly-houji-device.md#吞吐结果) · [Linux 6.1 mac80211 聚合文档](https://docs.kernel.org/6.1/driver-api/80211/mac80211-advanced.html#aggregation)

## RX BA，小米接收 Mac 的 A-MPDU

## 为什么 STA 路径不能直接套用

- `hdd_pt_iface_open` 明确跳过 STA 初始化和普通 Ethernet TX，建立独立 PASSTHRU vdev/PE。WMA 将 PASSTHRU 列为创建本地 self-peer 的角色，`wma_vdev_self_peer_create` 使用本机 vdev MAC，HDD 启动末尾注册和授权的也是本机 adapter MAC。这些都没有建立 Mac 的远端 peer 或其 BA TID。BSSID `02:00:00:00:00:07` 是 AWDL 帧的共同 BSSID，也不能作为远端 peer ID。普通 STA/LIM 的 RX 处理可参考，但要先证明管理帧从哪里抵达、哪个组件独占响应、remote peer/default route 在何处建立。普通 SME 发起 ADDBA 的入口则明确要求 `cm_is_vdevid_connected()`，随后把 vdev 的 BSSID 填作远端地址，两个假设均不适用于当前 AWDL。 [iface.c 89–110](../../driver/wlan/qcacld-3.0/core/hdd/src/wlan_hdd_passthru_iface.c#L89) · [MLME 2274–2289](../../driver/wlan/qcacld-3.0/components/mlme/core/src/wlan_mlme_vdev_mgr_interface.c#L2274) · [WMA 3112–3132](../../driver/wlan/qcacld-3.0/core/wma/src/wma_dev_if.c#L3112) · [control.c 352–362](../../driver/wlan/qcacld-3.0/core/hdd/src/wlan_hdd_passthru_control.c#L352) · [SME 8582–8608](../../driver/wlan/qcacld-3.0/core/sme/src/common/sme_api.c#L8582)
- 真实 BA 要在 vdev 退休前关闭新会话、等待操作和完成回调、退出/清空 REO、回收 peer ID，才可释放 vdev 和 DMA 内存。late event 必须核对 generation 和对象身份。当前 bridge 只为匹配 generation 的开放 provider 发 lease，HDD owner 已有关闭与排空顺序。新增控制应在同一所有权下绑定会话，不能跨 provider epoch 持有裸指针，也不能用一次 WMI ACK 代替 teardown 回执。 [bridge/wonder_lifecycle.inc 476–503](../../driver/bridge/wonder_lifecycle.inc#L476) · [owner.c 263–376](../../driver/wlan/qcacld-3.0/core/hdd/src/wlan_hdd_passthru_owner.c#L263) · [runtime.c 943–996](../../driver/wlan/qcacld-3.0/core/hdd/src/wlan_hdd_passthru_runtime.c#L943)

## 最小可逆验证

1. **先做只读观测版。** 从相同宽带树派生独立、默认关闭的候选，保持 149、BA=false、TX 上限 1、同一 Mac 与基准。只在现有长度/格式/对象验证之后统计 `peer-map`、HTT RX_ADDBA、REO 状态及 Kiwi RX 的 PPDU ID、真实 `ampdu_flag`、QoS TID、完整/拒绝 buffer 分类；只保留计数和关联所需字段。HAL 中名字含 `RAW_AMPDU` 的 bit 来自 `raw_mpdu`，与来自 `ampdu_flag` 的 bit 分开。缺少两种元数据时记录未知。首版只读候选先在 `build-host` 核对构建与 ABI。实际装载及生命周期验收单独安排。 [Kiwi HAL 1103–1122、2341](../../driver/wlan/qca-wifi-host-cmn/hal/wifi3.0/kiwi/hal_kiwi.c#L1103) · [PASSTHRU TLV 布局校验 3281–3312](../../driver/wlan/qca-wifi-host-cmn/hal/wifi3.0/hal_rx.h#L3281)
2. **用独立被动抓包校验。** 当前只确认了参与传输的小米与 Mac，独立被动接收器尚未确认可用。不能把传输 Mac 切到监听模式来代替它。取得独立接收器后，先核验 149 信道的 AMPDU status/PPDU 关联和控制帧可见性。先在现有 BA 关闭基线比对 ADDBA、正常 ACK、窗口和序号，区分抓不到控制帧与确实未发送。该阶段保持现有 raw 数据及固件命令路径，输出仅为诊断。现有 TQM 计数、`AMPDUCFG` 文本、MAC 层 ACK 与 A-MSDU 位分别记录。
3. **满足硬件前置证据后只做 RX/TID 0。** 先用可离线审计或基线观察确认所需 API/固件服务条件，以及 PASSTHRU 远端 peer、ID 映射、默认 route、REO 资源准备和可核验的就绪/清理回执。这些是进入受控协商的门槛。此前不要求看到协商后的硬件 BA。具备独立抓包后，在独立候选增加只对 allowlist Mac 开放的 RX 协商。初始最多一个 peer、一个 TID、一个方向。让确有队列和硬件就绪回执的单一控制面处理 ADDBA，未就绪则保持关闭。实际硬件回应是受控协商后的验收项。要同时看到同一 PPDU 的多个独立 MPDU、地址和 TID 匹配的真实 BA 位图，以及连续双向 64 MiB SHA-256。检查 DELBA、超时、peer 消失、异常停止后窗口/引用/模块/固件/Wi-Fi 和原 149/MCS3 Binder 恢复，再考虑反向 TX。该阶段只设计路线，本轮没有装载或启用。

## 只读候选的构建验证

首版补丁仅接入既有 PASSTHRU raw RX 交付函数。它统计通过原有检查的 raw buffer、Kiwi HAL A-MPDU 标志、相邻的同 PPDU 记录、A-MPDU QoS TID、clear BA Action 头部及原有拒绝点。HAL 布局无法验证时计入未知。此版没有 peer-map、HTT RX_ADDBA 或 REO 完成事件计数，因这些跨层事件须另外绑定 peer 与 vdev generation。没有新增管理帧发送、WMI 命令、REO 更新或队列所有权变化。 [补丁与操作说明](../../experiments/ba-observer/README.zh-CN.md) · [全局计数实机](16-ba-observer-device.md) · [单对端观测](17-rx-peer-reo-observer-plan.md)

候选在 `build-host` 的隔离树构建。ELF 核验通过，`pt_ba_observe` 初始值为 0，`pt_ba_observe` 和 `pt_ba_stats` 权限均为 `0444`。候选与两个现有宽带参照的 567 个导入及 CRC、导出 CRC、依赖、vermagic 和模块结构匹配。两个参照整文件 SHA 不同，可执行段哈希相同。链接器仍报告既有的两条 WLAN 栈帧尺寸警告，与上轮构建的函数和数值一致。完整调试产物留在 build-host，去除调试信息的交付副本也通过相同 ABI 检查。候选未装载到手机。 [构建日志](../../experiments/ba-observer/build.log) · [完整产物 ABI](../../experiments/ba-observer/audit.json) · [交付副本 ABI](../../experiments/ba-observer/audit-stripped.json)

目前的关键未知是当前 DZF2 `kiwi_v2` 固件在 **PASSTHRU 角色** 下是否接受未关联 AWDL remote peer、会否配置对应的 RX BA/REO，以及是否有能驱动 TX 窗口的真实反馈。通用 WLAN API、STA 实现和 Owly 的其它网卡 quirk 都提供了参照；结论需要该角色自己的命令回执、空口和数据证据。
